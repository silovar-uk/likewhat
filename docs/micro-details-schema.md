# MICRO DETAILS schema v1 / v2

## Purpose

`microDetails` stores small design decisions only when they are grounded in a specific reference. It is intentionally separate from the editorial fallback generated by `micro-details.js`.

The goal is not pixel-perfect copying. The goal is to preserve enough evidence to reproduce typography, spacing, surfaces, layout and interaction decisions without presenting estimates as official values.

## Evidence levels

Use one of these values for `traceLevel` and for each item's `method`:

- `curated` — a representative value/range selected after reviewing the reference.
- `observed` — directly visible in the reference, but not measured from CSS or a rendered box.
- `measured` — checked from CSS, developer tools, a documented token, or a measured rendered value.

`estimated` is never stored in pattern data. Estimates are runtime fallback only.

## Confidence

Each item must declare one of:

- `high`
- `medium`
- `low`

Confidence describes confidence in the observation, not design quality.

## Canonical shape

```js
microDetails: {
  schemaVersion: 1,
  traceLevel: 'observed',
  checkedAt: '2026-08-17',
  sources: [
    {
      id: 'official',
      label: 'Official reference',
      url: 'https://example.com/',
      kind: 'official'
    }
  ],
  groups: {
    typography: {
      cue: 'Large heading with a compact body measure.',
      items: [
        {
          label: 'Hero heading',
          value: '48–56px',
          confidence: 'high',
          method: 'observed',
          sourceId: 'official',
          note: 'Record a range when viewport-dependent.'
        }
      ]
    }
  }
}
```

## Allowed groups

- `typography`
- `spacing`
- `surface`
- `layout`
- `interaction`
- `components` (v2)
- `responsive` (v2)

Do not force all groups to be filled. Missing data is preferable to invented precision.

## v2 additions: relations and meaning

v1's `traceLevel` / `method` / `confidence` separation is unchanged in v2. v2 only adds
two **optional** per-group fields, for the "value → relation → meaning" ladder:

```js
groups: {
  typography: {
    cue: '...',
    items: [ /* same as v1 */ ],

    // v2, optional: a ratio or ordering between two items in this group.
    relations: [
      {
        label: 'Heading : Body',
        value: '3.5 : 1',
        from: 'Hero heading',   // must match an items[].label in the same group
        to: 'Body',             // must match an items[].label in the same group
        method: 'measured',
        confidence: 'high'
      }
    ],

    // v2, optional: what the relation is doing, in one sentence.
    meaning: {
      text: 'This large scale gap pulls attention to a single message.',
      basis: 'relations' // 'relations' | 'items' | 'editorial'
    }
  }
}
```

Set `schemaVersion: 2` when a pattern uses `relations`/`meaning` or the new groups.
Existing `schemaVersion: 1` records remain valid and are not migrated.

### Curated items must never look measured

If `method` is `curated`, `value` must be words, not a number-shaped string
(`"48px"`, `"1.5rem"`, `"3.5:1"`). Curated is an editorial read, not a measurement;
writing a number there is the single most likely way a guess gets mistaken for a fact.
Write `"large"` or `"tight"` instead. `scripts/check-micro-details.mjs` rejects
numeric-looking `curated` values.

### `measured` requires citable evidence

Any item with `method: 'measured'` must point (via `sourceId`) to a source whose
`kind` is `official` or `css` — not `screenshot` or `other`. A measurement without
a checkable origin is not a measurement.

### Library-wide cap

The corpus-wide count of patterns carrying a `microDetails` object must stay at or
below 20 (`scripts/check-micro-details.mjs` enforces this). This is a deliberate
brake on scope: depth over the whole library is not the goal of this rollout stage.

## Source kinds

- `official` — official brand/product/reference page
- `reference` — the exact page used for this pattern
- `css` — stylesheet, token documentation, or developer-tools evidence
- `screenshot` — dated visual capture used for observation
- `other` — evidence that does not fit the above

Every stored item must point to one `sourceId`.

## Recording rules

1. Prefer ranges when responsive behavior changes the value.
2. Do not write exact pixel values from visual guesswork. Use `observed` plus a range, or leave the item absent.
3. Use `measured` only when the measurement method is reproducible.
4. Record `checkedAt` every time a trace is reviewed against the live reference.
5. Preserve the reference URL even when the brand's general official site is already available elsewhere in Like What?.
6. Keep interpretation in `note` or `cue`; keep `value` compact and reusable.
7. Never upgrade confidence simply because several patterns from the same brand look similar.

## Rollout policy

- Stage 1: schema and validator only.
- Stage 2: 3 pilot patterns with different density/interaction characteristics.
- Stage 3: review field usefulness and revise schema only if necessary.
- Stage 4: expand to 10 representative patterns.
- Stage 5: scale to the wider library after the schema is stable.

A pattern without `microDetails` continues to use the runtime `EDITORIAL ESTIMATE` fallback.
